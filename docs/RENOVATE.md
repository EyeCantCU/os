# Renovate tips

Renovate can be run as an installed github app, github action, self-hosted github app, or locally against the github hosted repository.

Using `--platform=local` is dryrun only and check dependencies and versions, but does not create any branches, does not do any changes to any files and does not open PRs.

## Get CLI tool

Get renovate CLI tool

```
$ make dev-container
$ apk add renovate
```

## Check tracked deps locally

To quickly show a summary of how many files are detected with managed updates run:

```
$ renovate --platform=local
...
 INFO: Dependency extraction complete (repository=local)
       "stats": {
         "managers": {"regex": {"fileCount": 1, "depCount": 1}},
         "total": {"fileCount": 1, "depCount": 1}
       }
...
```
As you can see only one manager is activate (regex), and it has one file to update, with a single dep.

## Executed renovate against remote repository

Until renovate app is installed and running against the organization repositories, preffer to run renovate against own fork, review PRs it created, and then propose them to our main repository.

Generate github token:

```
$ gh auth token
gho_...
```

Also ensure your fork of enterprise-packages is up to date:

```
gh repo sync yourfork/stereo
```

Also export GIT variable to ensure commits generated by renovate, are attributed to it:

```
export GIT_AUTHOR_NAME="Renovate Bot"
export GIT_AUTHOR_EMAIL="renovate@example.com"
export GIT_COMMITTER_NAME="Renovate Bot"
export GIT_COMMITTER_EMAIL="renovate@example.com"
export RENOVATE_TOKEN=gho_...
renovate --platform=github yourfork/stereo
```
